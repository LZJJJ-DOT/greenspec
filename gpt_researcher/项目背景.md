# GreenSpec-Agent 项目背景

## 1. 项目定位

GreenSpec-Agent 是一个面向北京地区普通办公楼绿色建筑咨询场景的多 Agent 规范预审工作台。

项目聚焦方案设计与初步设计阶段，辅助绿色建筑咨询人员、设计院建筑师助理和甲方设计管理人员完成项目参数梳理、绿色建筑与节能规范检索、条文适用性研判、二星级预审、三星级差距分析、风险分级和证据链报告生成。

本系统不定位为自动审图工具，也不替代注册建筑师、绿建评审专家或施工图审查机构。它的核心价值是将分散的规范文件、项目参数和人工咨询经验组织成一个可复核、可追溯、可归档的预审流程，降低前期咨询阶段的漏检、错引和资料缺失风险。

## 2. 真实业务背景

在办公楼项目的方案设计和初步设计阶段，绿色建筑咨询通常需要提前介入。咨询人员需要根据项目所在地、建筑类型、面积、高度、功能、设计阶段、星级目标等信息，判断项目应满足哪些国家标准、地方政策和绿色建筑评价要求。

传统工作方式主要依赖人工查阅规范、整理表格和撰写预评估报告，常见痛点包括：

- 规范来源分散：国家标准、强制性工程建设规范、地方标准、住建部门政策、绿色建筑标识申报文件和企业内部校审表往往分散在不同来源。
- 条文适用条件复杂：同一条文是否适用，取决于地区、建筑类型、设计阶段、建筑面积、建筑高度、气候条件、系统方案和星级目标。
- 规范版本容易混用：绿色建筑、建筑节能、可再生能源、室内环境、节水、照明、采光等标准更新周期不同，人工整理时容易出现旧版条文或非适用地区文件混入。
- 结论缺少证据链：咨询报告不能只写“建议满足某要求”，还需要绑定标准编号、条文编号、页码、适用理由和待确认资料。
- 方案阶段资料不完整：很多能耗模拟、采光计算、围护结构热工参数、绿色建材比例、可再生能源系统方案在早期尚未稳定，导致很多结论只能做预判断和差距分析。

因此，本项目选择将问题收敛到“北京地区普通办公楼绿色建筑方案/初设预审”，用一个边界清晰的场景展示多 Agent 编排、规范知识库、RAG 检索、证据链生成和人工复核机制。

## 3. 用户场景

### 3.1 目标用户

第一版系统面向以下用户：

- 绿色建筑咨询工程师：需要快速完成二星级预审和三星级提升路径分析。
- 设计院建筑师助理：需要整理项目基础参数、适用规范清单和前期风险点。
- 甲方设计管理人员：需要在方案阶段了解项目距离绿建目标的差距。
- 内部校审人员：需要在正式申报或施工图深化前识别资料缺失和高风险条文。

### 3.2 典型项目

第一版建议使用一个模拟但贴近真实业务的项目案例：

```text
项目名称：北京某办公楼项目
建设地点：北京市
建筑类型：普通办公楼
设计阶段：方案深化 / 初步设计
绿色建筑目标：二星级预审，三星级差距分析
建筑面积：约 30000-50000 平方米
建筑高度：多层或高层办公建筑
主要输入：项目参数表、设计任务书、建筑设计说明、节能专篇初稿、绿建策划表
```

### 3.3 典型工作流

用户不是直接向聊天框提问，而是在网页工作台中完成一套咨询流程：

1. 创建项目，填写建设地点、建筑类型、建筑面积、高度、层数、容积率、绿地率、设计阶段、星级目标等参数。
2. 上传项目资料，包括设计任务书、建筑设计说明、节能专篇初稿和绿建策划表。
3. 系统抽取项目画像，并让用户确认关键字段。
4. 系统根据项目画像拆分规范研究任务。
5. 规范检索 Agent 从知识库中检索相关标准、条文和政策依据。
6. 条文适用性研判 Agent 判断条文是否适用，并标记适用、不适用、待确认。
7. 风险评估 Agent 输出强制性风险、星级达标风险、资料缺失风险和优化建议。
8. 报告生成 Agent 生成绿色建筑预审报告草稿。
9. 用户人工复核高风险项和低置信度结论后，系统生成可归档版本。

## 4. 为什么选择北京普通办公楼

### 4.1 为什么选择北京

北京的地区边界清晰，政策公开程度较高，绿色建筑、建筑节能、低碳设计和可再生能源利用相关要求较多，适合作为第一版 MVP 场景。

系统第一版不追求全国适配，而是先将北京地区的国家规范、地方政策和项目参数规则打通。后续可通过地区政策元数据扩展到上海、广东、浙江等地区。

### 4.2 为什么选择普通办公楼

普通办公楼比住宅更适合展示绿色建筑咨询场景。办公楼属于典型公共建筑，通常涉及建筑节能、可再生能源、照明、采光、通风、室内环境、水资源、场地交通、运行管理等多个维度。

与医院相比，办公楼不需要过多处理医疗流线、感染控制、洁净空间和特殊科室等高度专科问题，项目风险更可控。与住宅相比，办公楼的绿色建筑评分项和机电系统策略更丰富，更适合展示多 Agent 编排能力。

### 4.3 为什么是二星预审 + 三星差距分析

第一版不建议承诺“自动判断三星达标”。三星级绿色建筑通常需要更完整的专项数据和专业计算，包括能耗模拟、采光模拟、声环境分析、围护结构热工参数、可再生能源利用比例、绿色建材比例和运行管理方案等。

方案/初设阶段很多资料尚不稳定，系统更合理的定位是：

- 对二星级目标进行预审，识别明显风险和资料缺口。
- 对三星级目标进行差距分析，提示需要补充的专项计算、设计策略和人工复核点。

这种定位更贴近真实咨询工作，也能避免将 AI 包装成不可追责的自动合规判定工具。

## 5. 知识库建设

### 5.1 第一版知识库范围

第一版知识库不追求数量，而追求结构化质量。建议优先准备以下材料：

- 《绿色建筑评价标准》GB/T 50378-2019
- 《建筑节能与可再生能源利用通用规范》GB 55015-2021
- 《公共建筑节能设计标准》GB 50189
- 《民用建筑通用规范》GB 55031-2022
- 《建筑环境通用规范》GB 55016-2021
- 北京市绿色建筑标识管理相关文件
- 北京市绿色建筑、建筑节能、低碳设计相关地方政策或地方标准
- 项目参数表、设计任务书模板、节能专篇模板、绿建预评估表

### 5.2 知识库文件形态

原始资料可以保存为 PDF，但不建议直接把 PDF 丢给 RAG。推荐分为三层：

```text
/raw
保存原始 PDF、网页快照、政策文件和来源信息。

/processed
保存转换后的 Markdown 文本，便于人工校对和 LLM 阅读。

/index
保存结构化 JSONL、CSV、数据库记录和向量索引。
```

每个条文应尽量结构化，示例字段如下：

```json
{
  "standard_id": "GB/T 50378-2019",
  "standard_name": "绿色建筑评价标准",
  "clause_no": "5.x.x",
  "clause_title": "条文标题",
  "clause_text": "条文正文",
  "level": "控制项/评分项/加分项",
  "score": 5,
  "region": "national",
  "building_type": ["public", "office"],
  "design_phase": ["scheme", "preliminary_design"],
  "requires_calculation": true,
  "requires_manual_review": true,
  "source_file": "GB_T_50378_2019.pdf",
  "source_page": 32
}
```

对于绿色建筑评价标准中的表格，应尽量单独抽取为 CSV 或 JSON。评分项、分值、控制项、最低得分要求、星级门槛和适用条件比普通正文更重要。

### 5.3 OCR 处理策略

如果资料是图片版 PDF，可以接入 OCR 流程，但 OCR 结果不能直接作为最终可信条文。

推荐处理流程：

1. 优先使用文字版 PDF 或官方 HTML。
2. 图片版 PDF 进入 OCR 流程。
3. OCR 后保留页码、文本块位置和识别置信度。
4. 表格单独抽取并人工校对。
5. 低置信度条文标记为待人工确认，不直接进入最终报告结论。

可选技术包括 PaddleOCR、Tesseract、PyMuPDF、pdfplumber、Camelot、Tabula 等。中文规范和复杂表格场景下，应优先考虑带版面分析能力的 OCR 或人工校对流程。

## 6. RAG 与多 Agent 编排关系

本项目可以理解为 RAG 项目，但不能只停留在“向量检索 + 大模型回答”。更准确的定义是：

> 面向建筑绿色规范的元数据过滤型、条文级 RAG 与多 Agent 研判系统。

RAG 知识库主要服务于以下 Agent：

- 规范检索 Agent：根据项目画像检索相关规范、政策、条文和评分项。
- 条文适用性研判 Agent：结合项目参数判断条文是否适用，输出适用、不适用、待确认。
- 报告质控 Agent：检查每个结论是否绑定标准编号、条文编号、页码和来源文件。

完整链路如下：

```text
用户输入项目参数和项目资料
-> 项目画像 Agent
-> 任务编排 Agent
-> 规范检索 Agent 调用知识库/RAG
-> 条文适用性研判 Agent
-> 风险评估 Agent
-> 报告生成与质控 Agent
-> 人工复核与归档
```

## 7. 多 Agent 架构

第一版建议设计 6 个核心 Agent。

### 7.1 项目画像 Agent

负责从用户填写信息和上传资料中抽取项目基础参数，包括地点、建筑类型、建筑面积、建筑高度、层数、容积率、绿地率、设计阶段、绿建星级目标、是否公共建筑、是否涉及可再生能源等。

输出项目画像 JSON，作为后续检索和研判的结构化输入。

### 7.2 任务编排 Agent

根据项目画像拆分研究任务，例如绿色建筑评价、建筑节能、可再生能源、室内环境、水资源、场地交通、材料资源、运行管理等。

该 Agent 的价值是把用户的自然语言问题转化为可执行的规范研究计划。

### 7.3 规范检索 Agent

从结构化知识库中检索相关条文、评分项和政策文件。检索时不仅依赖语义相似度，还应结合标准编号、地区、建筑类型、设计阶段、条文类型、是否强制等元数据过滤。

### 7.4 条文适用性研判 Agent

结合项目参数判断检索到的条文是否适用，并输出适用理由、缺失参数、人工复核点和置信度。

输出状态包括：

```text
适用
不适用
待确认
资料不足
```

### 7.5 风险评估 Agent

对研判结果进行风险分级：

```text
P0：强制性或重大合规风险，必须人工复核
P1：绿色建筑星级达标风险
P2：资料缺失或设计说明不足
P3：优化建议或三星提升项
```

### 7.6 报告生成与质控 Agent

生成绿色建筑预审报告草稿，并检查报告中是否存在无来源结论、条文编号缺失、版本信息缺失、OCR 低置信度文本直接引用等问题。

报告最终应由人工确认后归档，系统不自动给出不可追责的合规结论。

## 8. 网页工作台设计

为了区别于普通聊天机器人，前端应设计成咨询工作台，而不是单一问答框。

建议页面包括：

- 项目中心：展示项目列表、地区、建筑类型、星级目标和预审状态。
- 项目画像页：填写或上传资料，展示系统抽取的项目参数。
- Agent 编排页：展示任务拆解、Agent 执行状态、输入输出和日志。
- 规范证据页：展示条文、来源、适用性判断、置信度和待确认参数。
- 风险清单页：按 P0/P1/P2/P3 展示问题。
- 报告页：生成、编辑和导出绿色建筑预审报告。

第一版可基于 gpt-researcher 原有前端快速改造，将普通研究报告流程替换为建筑绿色规范预审流程。

## 9. 项目边界

为了避免项目在面试中被质疑过度包装，需要明确边界：

- 不做自动施工图审查。
- 第一版不接入 CAD 图纸解析。
- 不承诺自动判定三星级达标。
- 不替代绿建专家、注册建筑师或审图机构。
- 不直接采信未经校对的 OCR 条文。
- 不将 RAG 检索结果直接等同于合规结论。

系统输出的是咨询预审报告和风险提示，最终结论需要人工审核。

## 10. 面试可讲亮点

项目的核心亮点可以概括为三点：

1. 面向真实绿色建筑咨询流程的多 Agent 编排

系统不是简单问答，而是按照项目画像、任务拆解、规范检索、条文研判、风险分级、报告质控和人工复核的真实流程组织 Agent。

2. 参数驱动的条文级 RAG

系统不仅做语义检索，还使用地区、建筑类型、设计阶段、星级目标、条文类型、是否强制、是否需要计算等元数据过滤，实现更贴近规范业务的检索和研判。

3. 可追溯证据链与人工复核机制

每个结论都需要绑定来源文件、标准编号、条文编号和页码。强制性风险、资料缺失、规范冲突、低置信度 OCR 和低置信度模型结论进入人工复核队列，避免 AI 直接输出不可追责的合规判断。
